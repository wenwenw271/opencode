# 用户向 OpenCode 询问：入口与完整运转流程

本文档说明「用户向 OpenCode 发起询问」的入口在哪里、请求如何进入会话、Agent 如何参与、以及从用户消息到 AI 回复与工具调用的完整代码流程。

---
本质上它实现了一个 LLM Agent Runtime Loop：持续读取会话状态 → 判断需要执行的任务（tool / subtask / compaction）→ 调用模型 → 写回消息 → 再继续循环，直到生成最终回复。

```
User Message
     │
     ▼
Session Loop
     │
     ├─ Subtask?
     │      └─ 执行 agent/tool
     │
     ├─ Compaction?
     │      └─ 压缩历史
     │
     ├─ Token Overflow?
     │      └─ 插入 compaction
     │
     └─ Normal LLM Step
            ├─ build prompt
            ├─ resolve tools
            ├─ call LLM
            └─ parse result

```



## 1. 入口概览

用户询问可通过以下方式进入 OpenCode，最终都会落到 **SessionPrompt.prompt** 或 **SessionPrompt.command**，再进入 **SessionPrompt.loop** 驱动会话与 LLM 调用。

| 入口 | 场景 | 入口代码位置 | 最终调用 |
|-----|------|--------------|----------|
| **HTTP API** | Web/App/SDK 发消息 | `server/routes/session.ts` | `SessionPrompt.prompt({ ...body, sessionID })` |
| **ACP (Cursor)** | IDE 内聊天 | `acp/agent.ts` → `sdk.session.prompt()` | 同上（通过 HTTP 调 OpenCode 服务） |
| **CLI** | `opencode run`、GitHub 等命令 | `cli/cmd/run.ts`、`cli/cmd/github.ts` | `SessionPrompt.prompt()` 或 `sdk.session.prompt()` |
| **Task 工具** | 主代理调用子代理 | `tool/task.ts` | `SessionPrompt.prompt()`（子会话） |

## 3. ACP 入口（Cursor 等 IDE）

- **协议**：ACP（Agent Communication Protocol）由 `@agentclientprotocol/sdk` 定义；Cursor 通过 ACP 与 OpenCode 通信。
- **入口**：`packages/opencode/src/acp/agent.ts` 中实现 ACP Agent，处理 `PromptRequest`。
- **流程**：
  1. `ACP` 收到 `prompt(params: PromptRequest)`（含 `sessionId`、`prompt` 等）。
  2. 解析当前会话的 `model`、`agent`（`session.modeId ?? Agent.defaultAgent()`）。
  3. 将 ACP 的 `prompt` 转成 OpenCode 的 `parts`（text/file/image/resource 等）。
  4. 若用户输入不是命令（不以 `/` 开头），调用 **`this.sdk.session.prompt({ sessionID, model, parts, agent, directory })`**，即请求本地或远程 OpenCode 的 **POST `/:sessionID/message`**，与 HTTP 入口汇合。
  5. 若是 `/command`，则调用 `this.sdk.session.command(...)`，对应 **SessionPrompt.command**。

## 4. SessionPrompt.prompt：创建用户消息并进入 loop

**文件**：`packages/opencode/src/session/prompt.ts`

**流程**：

1. **Session.get(sessionID)**、**SessionRevert.cleanup(session)**。
2. **createUserMessage(input)**：
   - **解析 Agent**：`Agent.get(input.agent ?? (await Agent.defaultAgent()))`，得到当前代理配置（含权限、prompt、model 等）。
   - **解析模型**：`input.model ?? agent.model ?? lastModel(sessionID)`。
   - 构造 **MessageV2.User**（含 `agent`、`model`、`variant` 等），处理 `parts`（文本、文件、MCP 资源、@agent 等）。
   - **Session.updateMessage(userMsg)**、**Session.updatePart(part)** 写入 DB。
3. **Session.touch(sessionID)** 更新会话时间。
4. 若配置了 `input.tools`，合并进 **session.permission** 并 **Session.setPermission**。
5. 若 **input.noReply === true**，直接返回刚创建的用户消息，不触发 AI。
6. 否则调用 **`return loop({ sessionID })`**，进入会话循环。

**相关代码**：

```156:184:packages/opencode/src/session/prompt.ts
export const prompt = fn(PromptInput, async (input) => {
  const session = await Session.get(input.sessionID)
  await SessionRevert.cleanup(session)
  const message = await createUserMessage(input)  // 内部 Agent.get / defaultAgent
  await Session.touch(input.sessionID)
  ...
  if (input.noReply === true) return message
  return loop({ sessionID: input.sessionID })
})
```

## 5. SessionPrompt.loop：会话循环与单轮处理

**文件**：`packages/opencode/src/session/prompt.ts`（约 273–721 行）

loop 是 **单会话** 的「拉取消息 → 决定任务 → 调用 LLM 或子任务/压缩 → 写回消息」的循环，直到没有待处理的用户消息或需要退出。

### 5.1 循环前准备

- **start(sessionID)** / **resume(sessionID)**：为该 session 分配或复用 **AbortController**，用于取消。
- **MessageV2.filterCompacted(MessageV2.stream(sessionID))**：按顺序取会话消息（已做 compaction 的合并视图）。

### 5.2 每轮循环中

1. **取 lastUser / lastAssistant / lastFinished**：从消息列表末尾向前扫描，得到「最后一条用户消息」「最后一条助手消息」「最后一条已结束的助手消息」。
2. **退出条件**：若存在已结束的助手消息且其 `finish` 不是 `tool-calls`/`unknown`，且 lastUser 在 lastAssistant 之前，则 **break**（本轮不再生成新回复）。
3. **step === 1 时**：可选 **ensureTitle(...)**，用 **Agent.get("title")** 调 LLM 生成会话标题。
4. **待处理子任务 (subtask)**：若存在未执行的 **MessageV2.SubtaskPart**（例如主代理通过 Task 工具派发的子代理任务）：
   - 创建一条 **Assistant** 占位消息，并创建 **Task 工具** 的 tool part（status: running）。
   - **TaskTool.execute(...)** 内部再调 **SessionPrompt.prompt(...)** 在子会话中执行，完成后 **Session.updatePart** 更新该 tool part 为 completed/error。
   - **continue** 下一轮。
5. **待处理压缩 (compaction)**：若有 **compaction** 类型的待处理任务，调用 **SessionCompaction.process(...)**，完成后 **continue**。
6. **上下文溢出**：若 **SessionCompaction.isOverflow(...)**，则 **SessionCompaction.create(...)** 插入压缩任务，**continue**。
7. **正常处理**：
   - **Agent.get(lastUser.agent)** 得到当前轮使用的代理。
   - **SessionProcessor.create({ assistantMessage, sessionID, model, abort })**：创建一条新的 **Assistant** 消息并得到 **processor**。
   - **resolveTools({ agent, session, model, processor, messages, ... })**：根据 **ToolRegistry** 与 **MCP** 解析出当前轮可用的 **tools**（受 agent.permission 与 session.permission 约束）。
   - 若有 **lastUser.format?.type === "json_schema"**，注入 **StructuredOutput** 工具。
   - 构建 **system**（环境 + InstructionPrompt + 可选结构化输出说明）。
   - **processor.process({ user: lastUser, agent, system, messages, tools, model, ... })**：见下一节。
   - 根据 **processor.message.finish**、**result**（stop/compact/continue）决定 **break** 或 **SessionCompaction.create** 后 **continue**。
8. 循环结束后 **SessionCompaction.prune(sessionID)**，若有等待中的 callbacks，**resolve** 最后一条助手消息并 **return**。

**相关代码（正常分支）**：


## 6. SessionProcessor.process：调用 LLM 并消费流

**文件**：`packages/opencode/src/session/processor.ts`

**职责**：在 **单条 Assistant 消息** 上，循环「调用 LLM → 消费 fullStream → 执行工具/写 part → 若有 tool-calls 则把结果再次作为输入继续调用 LLM」，直到模型返回非 tool-calls 或出错/取消。

**流程**：

1. **while (true)** 内：
   - **stream = await LLM.stream(streamInput)**，其中 `streamInput` 包含：`user`、`sessionID`、`model`、`agent`、`system`、`messages`、`tools`、`abort` 等。
   - **for await (const value of stream.fullStream)**：
     - **start**：SessionStatus.set(sessionID, { type: "busy" })。
     - **reasoning-start/delta/end**：写入 reasoning part 并 **Session.updatePart** / **updatePartDelta**。
     - **tool-input-start**：创建 tool part（pending），记入 `toolcalls[value.id]`。
     - **tool-call**：更新 part 为 running、写入 input；若检测到 **doom_loop**（同一工具同参数连续多次），则 **PermissionNext.ask({ permission: "doom_loop", ... })**。
     - **tool-result**：**Session.updatePart** 将对应 tool part 标为 completed，写入 output。
     - **tool-error**：将 part 标为 error；若为权限/Question 拒绝且配置要求 break，则 **blocked = true**。
     - **start-step**：Snapshot.track()；写 step-start part。
     - **finish-step**：计算 **Session.getUsage**，更新 assistant 的 cost/tokens；写 step-finish part；**SessionSummary.summarize**；若 **SessionCompaction.isOverflow** 则 **needsCompaction = true**。
     - **text-start/delta/end**：写入或增量更新 text part。
     - **finish**：本轮流结束。
   - 若 **needsCompaction** 或 **blocked** 或 **assistantMessage.error**，返回 **"compact"** 或 **"stop"**；否则若本轮有 tool-calls，**streamInput** 中会包含新消息，**continue** 再次 **LLM.stream**；否则 **return "continue"** 或 **"stop"**。
2. 异常时：**SessionRetry** 可重试；或写入 **assistantMessage.error**、**Bus.publish(Session.Event.Error)**，并 **SessionStatus.set(idle)**。

**相关代码**：

## 7. LLM.stream：组装参数并调用 Provider

**文件**：`packages/opencode/src/session/llm.ts`

**职责**：根据 **agent**、**model**、**user**、**system**、**messages**、**tools** 组装成 AI SDK 所需参数，调用 **streamText**，返回流结果（供 SessionProcessor 消费 fullStream）。

**要点**：

- **System**：优先使用 **agent.prompt**；否则（非 Codex 时）**SystemPrompt.provider(model)**；再拼接 **input.system**、**input.user.system**。
- **Plugin.trigger("experimental.chat.system.transform", ...)** 可改写 system。
- **Provider.getLanguage(input.model)** 得到语言模型实例；**Config.get()**、**Provider.getProvider**、**Auth.get** 用于选项与鉴权。
- **resolveTools(input)**：根据 **PermissionNext** 与 **user.tools** 过滤掉被禁用工具。
- **streamText** 参数：**temperature/topP/topK** 来自 agent 或 ProviderTransform；**providerOptions**、**tools**、**toolChoice**、**messages**（system + 历史）、**abortSignal**、**maxRetries** 等。

## 8. 工具解析与权限（resolveTools）

**文件**：`packages/opencode/src/session/prompt.ts`（**resolveTools**，约 731–912 行）

- **ToolRegistry.tools({ modelID, providerID }, agent)**：根据模型与代理从注册表取工具列表，转成 AI SDK 的 **tool**，**execute** 内使用 **Tool.Context**（sessionID、messageID、callID、**ask**、metadata 等）。
- **PermissionNext.ask**：在 **Tool.Context.ask** 中调用，合并 **agent.permission** 与 **session.permission**，决定是否允许本次工具调用（allow/deny/ask 用户）。
- **MCP.tools()**：将 MCP 工具同样包装成 **tool**，execute 中先 **ctx.ask** 再执行，输出经 **Truncate.output** 等处理。
- 插件：**tool.execute.before** / **tool.execute.after** 在每次工具执行前后触发。

## 9. 数据流小结（从用户发问到回复）

```
用户发问（HTTP / ACP / CLI）
    ↓
POST /:sessionID/message 或 sdk.session.prompt()
    ↓
SessionPrompt.prompt({ sessionID, agent?, model?, parts, ... })
    ↓
createUserMessage → Agent.get(agent ?? defaultAgent()) → Session.updateMessage/updatePart
    ↓
loop({ sessionID })
    ↓
取 lastUser / lastAssistant；处理 subtask / compaction / overflow
    ↓
Agent.get(lastUser.agent)；SessionProcessor.create(assistantMessage, ...)
    ↓
resolveTools(agent, session, model, processor, messages) → tools
    ↓
processor.process({ user, agent, system, messages, tools, model })
    ↓
while (true) {
  LLM.stream(streamInput) → streamText(agent.prompt/system, messages, tools, model)
  for await (value of stream.fullStream)
    → tool-call → 权限 ask → 工具 execute → tool-result
    → text-delta → updatePartDelta
    → finish-step → getUsage、summarize、compaction 判断
  → 若 finish 为 tool-calls，继续下一轮 LLM.stream；否则 return stop/continue/compact
}
    ↓
loop 根据 result 决定 break 或 SessionCompaction.create 后 continue
    ↓
返回最后一条 Assistant 消息（或通过 stream/callback 返回给客户端）
```

## 11. 与 Agent 文档的关系

- **Agent 模块**（`原理/agent.md`）说明代理如何被**定义与解析**（state、get、list、defaultAgent、generate）。
- 本文档说明代理在**用户询问流程中**何时被使用：
  - **createUserMessage**：`Agent.get(input.agent ?? (await Agent.defaultAgent()))`；
  - **loop**：`Agent.get(lastUser.agent)`、子任务用 `Agent.get(task.agent)`；
  - **resolveTools**：使用 `agent.permission` 与 ToolRegistry 按代理过滤工具；
  - **LLM.stream**：使用 `agent.prompt`、`agent.options`、temperature/topP 等。

两者结合即可从「配置与解析」到「请求入口 → 会话循环 → LLM 与工具」完整理解 OpenCode 的运转流程。
