# 计划任务管理与执行保证

本文档说明 opencode 如何管理「计划任务」（Todo 列表）、以及是否/如何保证每一项都被执行。

---

## 一、结论概览

- **计划任务的管理**：按会话存一份 todo 列表（DB）；模型通过 **TodoWrite** 工具多次写入「完整列表」来维护（新建、进行中、完成、取消）。每次写入都是**整表覆盖**该会话的 todo，没有单条追加或只改状态的接口。
- **执行保证**：**没有代码级强制**。loop 不会在结束时检查「是否还有未完成 todo」；是否「做完再结束」完全依赖**系统提示**要求模型（如「必须把所有 todo 打勾再结束」）。若模型提前结束，opencode 不会拦截或自动续跑。

---

## 二、计划任务的存储与管理

### 2.1 存储位置与结构

- **模块**：`session/todo.ts`
- **表**：`session/session.sql.ts` 中的 **TodoTable**，按 `session_id`、`position` 存储
- **单条结构**（`Todo.Info`）：
  - `content`：任务描述
  - `status`：`pending` | `in_progress` | `completed` | `cancelled`
  - `priority`：`high` | `medium` | `low`

### 2.2 写入：TodoWrite → Todo.update

- **入口**：主 agent 调用 **TodoWrite** 工具（`tool/todo.ts`），参数为 `todos: Todo.Info[]`（完整列表）。
- **实现**（`session/todo.ts`）：
  - `Todo.update({ sessionID, todos })` 先 **delete 该 sessionID 下所有行**，再 **insert 本次传入的 todos**（带 position）。
  - 即：**每次调用都是整表覆盖**，没有「只追加一条」或「只改某条 status」的 API；模型要更新状态就必须在下次 TodoWrite 时带上整份列表（含已完成项的 status）。

### 2.3 读取：Todo.get

- `Todo.get(sessionID)` 按 `session_id` 查询，按 `position` 排序返回数组。
- **使用方**：
  - **TodoRead** 工具（`tool/todo.ts`）：执行时调 `Todo.get(ctx.sessionID)` 返回给模型。
  - **API**：`GET /:sessionID/todo`（`server/routes/session.ts`）供前端或外部读取。
- **注意**：默认 **TodoRead 未注册进主 agent**（在 `tool/registry.ts` 里被注释掉），因此主 agent 通常**没有**「读 todo」工具，只能通过**上一次 TodoWrite 的工具返回**在对话上下文中看到当前列表。

### 2.4 事件与同步

- `Todo.update` 后会发布 `Todo.Event.Updated`（sessionID + todos），便于前端/ACP 等订阅并刷新 UI（如 Cursor 侧边栏计划列表）。

## 三、「确保每项都执行」是否有保障

### 3.1 代码层面：无强制

- **Loop 结束条件**（`session/prompt.ts`）：当模型返回的 finish 不是 `tool-calls`/`unknown`，或达到 max steps、或出错时，loop 即结束。
- **没有**以下逻辑：
  - 在每轮结束前检查 `Todo.get(sessionID)` 是否还有非 completed 项；
  - 若有未完成项则禁止结束或自动追加一条「请继续完成剩余 todo」的 user 消息；
  - 任何「必须执行完所有 todo 才能 exit」的硬性校验。

因此：**从实现上看，opencode 并不保证每个计划任务都会被执行；它只提供「存一份列表 + 在对话中通过工具结果展示/更新」的能力。**

### 3.2 提示词层面：要求模型「做完再结束」

「尽量做完再结束」完全依赖**系统提示**和**工具描述**对模型行为的约束，例如：

- **anthropic.txt**（常规主 agent）：
  - 要求使用 TodoWrite **非常频繁**地规划和跟踪任务；
  - 做完一项就**立即**把对应 todo 标为 completed，不要攒一批再标；
  - 明确写：**Always use the TodoWrite tool to plan and track tasks throughout the conversation.**

- **beast.txt**（偏「自主跑到底」的 agent）：
  - **You MUST keep working until the problem is completely solved, and all items in the todo list are checked off.**
  - **Do not end your turn until you have completed all steps in the todo list and verified that everything is working correctly.**
  - 若用户说 "resume" / "continue" / "try again"，要从历史中找出 todo 列表，从**第一个未完成项**继续，直到**整份列表都打勾**再交回用户。

即：**「确保每个任务都执行」是「模型被要求这样做」的结果，而不是运行时有一个「执行完检查」的机制。** 若模型提前结束，opencode 不会强制继续或拦截。

## 四、流程小结

| 方面 | 说明 |
|------|------|
| **计划任务存哪** | 按 `sessionID` 存在 DB（TodoTable），每个会话一份列表；每条有 content、status、priority、position。 |
| **谁在维护列表** | 模型：通过多次调用 **TodoWrite**，每次传入**完整列表**（含更新后的 status 等），实现新建、进行中、完成、取消。 |
| **主 agent 能否读列表** | 默认未注册 TodoRead，主要靠**上次 TodoWrite 的工具返回**在对话中看到列表；服务端/API 可调用 `Todo.get(sessionID)` 读取。 |
| **如何「确保」每项都执行** | **无代码保证**；靠系统提示要求模型「规划 → 执行 → 打勾 → 全部完成再结束」。若模型提前结束，不会强制续跑。 |
