使用本工具创建并管理当前编码会话的结构化任务列表，便于跟踪进度、组织复杂任务并向用户展示完成度，也有助于用户了解任务进展与整体请求的进度。

## 何时使用本工具
在以下场景中应主动使用：

1. 复杂多步骤任务——需要 3 个及以上独立步骤或操作时
2. 非平凡且复杂的任务——需要仔细规划或多次操作时
3. 用户明确要求任务列表——用户直接要求使用任务列表时
4. 用户给出多项任务——用户提供多件待办（编号或逗号分隔）时
5. 收到新指令后——立即将用户需求记入 todo，可根据新信息编辑列表
6. 完成一项任务后——标记完成并添加后续任务
7. 开始新任务时——将对应 todo 标为 in_progress。理想情况下同一时间仅有一个 todo 为 in_progress。先完成既有任务再开新任务。

## 何时不要使用本工具

在以下情况可跳过：
1. 仅有一个简单直接的任务
2. 任务过于琐碎，跟踪无助于组织
3. 任务可在少于 3 个简单步骤内完成
4. 纯对话或信息类请求

注意：若只有一个琐碎任务，不必使用本工具，直接执行即可。

## 使用任务列表的示例

<example>
用户：我想在应用设置里加一个深色模式开关，做完后跑一下测试和构建！
助手：好的，帮你在设置里加深色模式开关。先建一个任务列表来跟踪实现。
*创建包含以下条目的任务列表：*
1. 在设置页创建深色模式开关组件
2. 添加深色模式状态管理（context/store）
3. 实现深色主题的 CSS-in-JS 样式
4. 更新现有组件以支持主题切换
5. 运行测试与构建流程，并解决失败或错误
*开始执行第一项*

<reasoning>
助手使用任务列表的原因：
1. 添加深色模式涉及多步：UI、状态、样式
2. 用户明确要求完成后跑测试和构建
3. 助手将「确保测试与构建通过」作为最后一项
</reasoning>
</example>

*创建针对每个需修改文件的具体任务*

<reasoning>
助手使用任务列表的原因：
1. 先搜索以了解范围
2. 发现多处出现后判定为多步骤复杂任务
3. 任务列表保证每处都被跟踪并统一修改

助手：好的，先把这些功能都放进任务列表。

<reasoning>
助手使用任务列表的原因：
1. 用户给出了多个复杂功能（逗号分隔）
2. 任务列表有助于把大功能拆成可管理步骤
3. 便于跟踪整体实现进度
</reasoning>
</example>

<example>
用户：能帮我优化 React 应用吗？渲染慢、有性能问题。
助手：先看一下代码库，找出可能的性能瓶颈。
*检查组件结构、渲染方式、状态与数据请求*
助手：分析后有几处性能问题，建个任务列表来跟踪优化。
*创建如：1) 在 ProductList 中对昂贵计算做 memo，2) Dashboard 长列表虚拟化，3) Gallery 图片加载优化，4) ShoppingCart 状态更新循环修复，5) 检查 bundle 并做代码分割*
先从 ProductList 的昂贵计算 memo 开始。

<reasoning>
助手使用任务列表的原因：
1. 先检查代码库定位具体问题
2. 据此识别多处可优化点
3. 性能优化是非平凡的多步骤任务
4. 任务列表便于按组件逐项改进
5. 系统化处理可覆盖主要瓶颈
</reasoning>
</example>

## 不应使用任务列表的示例

<example>
用户：Python 里怎么打印 'Hello World'？

python
print("Hello World")

<reasoning>
未使用任务列表是因为这是单一、琐碎的一步任务，无需跟踪多步骤。
</reasoning>

<example>

助手：git status 显示工作区与暂存区的当前状态，包括已暂存、未暂存和未跟踪的文件，用于在提交前了解仓库状态。

<reasoning>
未使用任务列表是因为这是信息类问题，没有实际编码任务或多步骤要执行。
</reasoning>
</example>

<example>

*用 Edit 工具在 calculateTotal 处添加注释*

<reasoning>
未使用任务列表是因为这是单一、直接的任务，只涉及一处修改。
</reasoning>
</example>

<example>

[npm install 输出]

## 任务状态与管理

1. **任务状态**：用以下状态跟踪进度：
   - pending：未开始
   - in_progress：进行中（同时仅限一个）
   - completed：已完成
   - cancelled：不再需要

2. **任务管理**：
   - 随工作进展实时更新状态
   - 完成后立即标为 completed（不要攒着一起标）
   - 任意时刻仅有一个任务为 in_progress
   - 先完成当前任务再开新任务
   - 对已无关的任务标为 cancelled

3. **任务拆分**：
   - 拆成具体、可执行的小项
   - 把复杂任务拆成可管理步骤
   - 使用清晰、描述性的任务名

有疑问时可以使用本工具。主动做好任务管理能体现对需求的关注，并有助于完整完成所有要求。
